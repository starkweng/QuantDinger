H5 AI Trading Flight Control PRD v0.3

把 10 分价值标准落成第一版可开发范围：Research Evidence、StrategySpec、Scenario、Risk、Signal/Paper、Ledger、Weekly Review。

回总览 看 P0

PRD v0.3 的结论：第一版只做交易飞控 MVP，先证明“少做坏交易”。

本版本不追求交易功能大而全，也不追求第一天接 live API。P0 的唯一任务，是让系统每天能够围绕一个标的完成：有来源 research、H5 结构判断、A/B/C/D 场景推演、最大亏损计算、风控通过或拒绝、Signal/Paper 输出、Decision Ledger 记录、Weekly Review 复盘。

10 分价值的第一性证明不是收益曲线，而是：系统能否在真实工作流中阻止坏交易、约束亏损、让等待有依据、让复盘能进化。
ProductFlight Control交易飞控系统，不是交易机器人。
P0 ModeSignal + Paper默认不接真钱执行。
Hard GateRisk Kernel风控拥有最终否决权。
North StarBad Trade Avoided先证明少犯错。

1. 问题定义

为什么这个项目值得做，但第一版必须收窄。

Problem

用户不缺信号

交易市场里永远有开仓理由。真正稀缺的是不下单的纪律、亏损上限、等待条件和事后复盘。

AI 会放大错误

AI 接 API 后，下单更快，错误也更快。没有硬风控和审计，AI 交易系统会变成加速器。

H5 的价值在框架

H5 不是单指标策略，而是市场状态、周期、中轴、价量、评分、资管和执行门控的决策框架。

产品机会：把 H5 的观察框架和你的交易哲学，放进 QuantDinger 的自托管量化骨架里，再用多 agent research 和 Risk Kernel 把它变成每天可用的交易飞控系统。

3. 角色与用户故事

第一版先服务 Stark 自用工作流，但接口要为后续团队化留下边界。

Users

Operator / Stark

  • 作为交易操作者，我要快速知道现在能不能做、为什么做或不做、最多亏多少。
  • 作为交易操作者，我要在临盘前看到 A/B/C/D 预案，而不是临场猜测。
  • 作为交易操作者，我要在风控拒绝时看到可解释原因，避免把拒绝当成系统故障。

Research Agent Team

  • 作为 research agent，我只能输出证据、观点、反方和风险，不允许下单。
  • 作为 risk officer，我只能批准、拒绝、降级、冻结，不允许生成方向信号。
  • 作为 growth curator，我只能提出候选改进，不允许自动修改 live 策略。

4. P0 页面结构

第一版页面为真实工作流服务，不做营销首页。

Screens

Flight Cockpit

第一屏。显示市场状态、H5 分数、风险预算、执行模式、是否允许交易、下一步动作。

Research Desk

创建研究任务、查看 evidence packet、bull/bear/risk 辩论、来源新鲜度和结论影响。

H5 StrategySpec

编辑 H5 字段：中轴、确认周期、Keltner、MA、结构、评分、失效条件和风险模板。

Scenario Planner

展示 A/B/C/D 路径，每条路径包括触发条件、等待条件、操作、失效、最大亏损。

Risk Kernel

展示账户状态、策略预算、单笔风险、日损、连续亏损、Kill Switch 和拒绝日志。

Signal / Paper Desk

生成 Signal Card 和 Paper Order Intent；支持手工标记是否执行、是否错过、是否有效。

Decision Ledger

审计所有研究、信号、拒绝、等待、撤销、止损和错过机会。

Weekly Review

一周复盘，输出策略保留/降级/测试/禁止清单和下一周 watchlist。

5. 核心流程

P0 只跑一条价值链。

Workflow
01Watchlist

选择标的、市场、时间窗口、交易计划。

02Research

生成有来源 evidence packet 和反方观点。

03H5 Judge

选择中轴，计算结构、价量、波动、点位评分。

04Scenario

生成 A/B/C/D 场景和触发/失效条件。

05Risk

计算最大亏损，给出批准、拒绝或降级。

06Signal/Paper

只生成信号和 paper intent，不直接真钱执行。

07Ledger/Review

记录结果，并进入 weekly review。

P0 happy path: research_mission -> evidence_packet -> h5_signal_card -> scenario_plan -> risk_decision -> paper_order_intent -> decision_ledger -> weekly_review P0 rejection path: research_mission -> evidence_packet -> h5_signal_card -> scenario_plan -> risk_rejected -> decision_ledger(reason) -> weekly_review(bad_trade_avoided)

7. 状态机与权限

没有状态机，就没有交易飞控。

Gates

Strategy State

  • draft：只能编辑和研究。
  • backtest_ready：可导出 Pine/Python，不允许执行。
  • paper_enabled：允许 paper intent。
  • shadow_observing：真实行情影子记录。
  • semi_auto_candidate：后续阶段候选。

Account State

  • normal：按常规风险。
  • conservative：降低风险预算。
  • reduce_only：只允许减仓/复盘。
  • frozen：禁止新 signal 升级。
  • manual_review：需要人工复核。

Execution Mode

  • SIGNAL_ONLY：P0 默认。
  • PAPER：P0 可用。
  • SEMI_AUTO：P1/P2 候选。
  • AUTO_API：P0 禁止。
  • KILL_SWITCH：任何阶段最高优先级。
主体允许禁止

H5 Agent计算评分、结构、场景绕过风控、输出交易命令

8. 成功指标与验收标准

10 分产品按行为质量验收，不按页面数量验收。

Metrics
指标P0 目标计算方式意义
Bad Trade Avoided每天可记录risk_rejected 或 wait_decision 后价格验证证明系统减少坏交易。
Max Loss Known Rate100%有 max_loss 的 signal / 全部 signal证明先控亏损。
Evidence Coverage90%+有来源 evidence 的 decision / 全部 decision证明不是拍脑袋。
Risk Rejection Quality可解释率 95%+有 reason + rule_id 的 rejection / 全部 rejection让拒绝可复盘。
Scenario Prepared重点标的 100%有 A/B/C/D 的 watch item / 重点 watch item证明不临盘乱猜。
Review Conversion每周输出weekly_review 生成候选改进数量证明系统会成长。
不作为 P0 成功指标：实盘收益率、策略市场规模、自动下单次数、信号数量、AI 自信分。它们会把产品带偏。
