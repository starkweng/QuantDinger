1. 问题定义：为什么不是再做一个“信号系统”

如果产品目标只是更快地提示买卖，AI 反而会放大交易者最坏的冲动。

PM framing
用户真实问题
交易者不缺“开仓理由”，缺的是 不交易的纪律、失败后的止损、交易前的预案、跨市场信息整合、以及在不同模式下可审计的执行授权。AI 接 API 后下单更容易，错误也会更快、更大。
产品机会
把 H5 的观察框架、Excel 规则、金木水火土理念、均线/中轴/波动/价量时空/资金管理，变成机器可执行的 StrategySpec + Risk Kernel + Scenario Planner + Execution Desk。
核心约束
系统必须承认市场不可预测，只能推演。每次动作要有条件、目的、风险预算和退出规则。没有足够证据时，产品要给出“等待/拒绝/只允许信号”的状态，而不是硬凑交易机会。

目标用户

主动交易者、量化研究者、crypto + TradFi 融合操盘团队、希望用 AI research 但不想失控自动交易的人。

不服务谁

只想要“必中买卖点”、不愿设置止损、不接受风控拒绝、不愿复盘的人。这个系统不迎合赌博型使用。

第一性指标

不是信号数量，而是净收益、最大回撤、单笔最大亏损可控率、风控拒绝后的误伤率、以及等待纪律。

3. H5 交易系统理解：不是 H5 原则，而是一套可结构化的交易操作系统

这部分明确 H5 的逻辑价值，避免只做成理念口号。

H5 core

观察层

价、量、时间、空间、市场状态、趋势阶段、波动环境。AI 先观察，不急着判断。

结构层

中轴、均线成本、Keltner 通道、ATR 风险距离、支撑阻力、2B、量能突变、Wyckoff 结构。

决策层

评分不是买卖按钮，而是准入门槛。达标后也只进入信号或待执行状态。

资管风控层

从 Excel 两套资金管理中抽象参数模板，按账户、品种、波动、交易时长适配。

关键产品化解释

  • 中轴不是固定周期：它由品种波动和交易时长决定。日内交易通常落到 5m/15m，中短线可上移到 1h/4h/1d。
  • Keltner 不是神秘指标：它用 EMA/SMA 中线加 ATR 通道描述波动边界，用来判断价格相对中轴的位置、风险距离和过度偏离。
  • 评分达标不是自动下单：达标只说明“允许进入下一层判断”。是否挂单取决于前端执行模式和 Risk Kernel。
  • 金木水火土是认知框架：用来组织市场状态、节奏、能量、收敛发散和纪律，不替代可验证规则。

H5 的真正价值

它不是告诉 AI “这个指标金叉就买”，而是要求 AI 每次回答：当前市场处于什么状态？如果未来 60 分钟走到 A/B/C/D，分别怎么处理？如果错了最多亏多少？如果没有足够空间，为什么不做？

  • 会等待，是产品能力。
  • 会认输，是风控能力。
  • 会记录，是进化能力。
  • 会拒绝交易，是长期生存能力。

4. 产品架构：从数据到执行的完整闭环

这张图是后续开发和 Figma 的主线，不是装饰图。

system flow
1 Input Market / Broker / News Data

Binance、tokenized equities、Alpaca、IBKR、MT5、贵金属、原油、外汇、新闻和宏观事件。

2 Research Multi-Agent Research Desk

价格行为、VSA、Wyckoff、TradFi、新闻、反方辩论、风险官分工产出 brief。

3 Strategy H5 StrategySpec

Excel 规则结构化：时间级别、中轴、Keltner/ATR、评分、入场条件、失效条件。

4 Scenario Scenario Planner

推演未来 15/30/60 分钟 A/B/C/D 路径，不预测，只准备条件动作。

5 Risk Risk Kernel

检查单笔亏损、日亏损、连续亏损、仓位、盈亏比、波动、模式权限和 Kill Switch。

6 Execute Execution Desk

SIGNAL_ONLY、SEMI_AUTO、AUTO_API。全部由前端命令和风控授权决定。

7 Learn Audit / Review / Evolution

下单、不下单、撤单、止损、拒绝都记录，并进入复盘、参数更新和 agent 进化。

核心对象

  • AssetProfile：品种、市场、波动、交易时段。
  • StrategySpec：H5 参数、规则、阈值。
  • ResearchBrief：多 agent 研究结论。
  • ScenarioPlan：A/B/C/D 路径预案。

执行对象

  • Signal：只提示，不挂单。
  • OrderIntent：半自动挂单意图。
  • ExecutionMode：前端授权模式。
  • RiskDecision：放行、降级、拒绝。

审计对象

  • DecisionLog：每次判断和原因。
  • RiskEvent：触发风控和拒绝原因。
  • ReviewNote：复盘结论。
  • VersionChange：策略参数变更历史。

5. 可行性验证：能做什么、先做什么、哪些不能直接实盘

这一节来自网络资料、官方文档和多 agent 交叉验证；目的是把产品边界讲实。

feasibility gate

TradingView / Pine 回测 可做 P1

TradingView 策略脚本可以在历史和实时数据上模拟订单、查看 Strategy Tester，但它本质是 broker emulator，不等于真实成交。

  • 适合：验证 H5 条件、Keltner/ATR、止损止盈、时间过滤、基础盈亏比。
  • 不适合：证明真钱盈利、证明真实滑点、证明挂单队列和冲击成本。
  • 产品决策：Pine 是第一道快速筛选，不是上线凭证。

Binance 行情 / 执行 P0 数据，P2 实盘

Binance Spot/Futures 官方 API 支持深度、K线、成交、ticker、交易端点和签名请求，足够支撑 crypto 数据层和后续执行层。

  • 适合：BTC/ETH/主流币 K线、深度、成交额、波动、订单簿状态。
  • 执行限制：API key 权限、签名、recvWindow、rate limit、订单状态都必须进入风控和审计。
  • 产品决策：MVP 只接 public data + paper；实盘必须到 P2。

TradFi / 股票 / 贵金属 / 原油 分层接入

Alpaca 和 IBKR 都能支撑 paper trading 或 API 接入，但真实市场数据权限、地区限制、订单撮合差异和账户条件都不是小问题。

  • Alpaca 适合先做美股/crypto paper，官方明确 paper 和 live 可能不同。
  • IBKR 覆盖广，但 TWS/IB Gateway、权限、订阅、异步订单状态复杂。
  • 产品决策：TradFi 先做 Research + Paper Adapter，不直接承诺全品类自动交易。

TradingAgents 多 agent 可深学

TradingAgents 的公开框架把基本面、情绪、新闻、技术、Bull/Bear debate、Trader、Risk、Portfolio Manager 串起来，适合改造成 H5 research pipeline。

  • 适合：多工种 agent 分析、反方辩论、风险团队、最终组合经理审批。
  • 不适合：直接把 LLM 输出当交易命令。
  • 产品决策：agent 只能产出 ResearchBrief / RiskOpinion / TradeProposal，不能越权下单。

Keltner / ATR / 中轴 可量化

Keltner 常见现代版本是 EMA 中线加 ATR 通道；它应该用于波动边界、趋势状态、偏离距离和止损参考，不应被产品写成单一买卖神谕。

  • H5 用法：中轴周期随品种波动和交易时长变化，日内优先 5m/15m。
  • 字段化：centerline_tf、kc_length、atr_length、atr_mult、distance_to_mid、channel_position。
  • 产品决策：Keltner 是 RiskDistance / RegimeFeature，不是 auto-buy trigger。

AI 安全 / Agent 权限 必须 P0

OWASP LLM Top 10 明确提示 Prompt Injection、Insecure Output Handling、Excessive Agency 等风险。交易系统一旦接 API，这些不是理论风险。

  • 必须做：agent scope、最小权限、工具白名单、敏感操作二次确认、审计日志。
  • 必须禁：research agent 直接调用交易 API、网页内容直接覆盖系统规则、无签名无审批的自动下单。
  • 产品决策：Risk Kernel 和 Permission Kernel 都是 P0，不是上线后补。

验证路线：从“能跑”到“能用真钱”必须过 5 道门

GATE 01Research Only

只抓数据和生成研究 brief，不产生订单意图。

GATE 02Pine / Python 回测

同一 StrategySpec 在 Pine 和 Python 中验证，不看单次神迹，看样本外稳定性。

GATE 03Paper Trading

使用 Binance testnet / Alpaca paper / IBKR paper 验证订单生命周期和异常处理。

GATE 04Shadow Mode

跟随真实市场生成订单建议但不成交，对比实际成交可行性和滑点。

GATE 05Limited Live

极小资金、严格 kill switch、人工确认、日志完备后才允许 AUTO_API。

多 agent 交叉验证后的硬结论

产品架构结论

深抄 QuantDinger 的生命周期，而不是照搬 UI：Idea -> Indicator -> Strategy -> Backtest -> Paper/Shadow -> Execute -> Monitor。H5 每个策略必须有状态：draft、backtested、paper_running、shadow_passed、semi_auto_enabled、live_locked。

策略回测结论

Pine 用于验证规则骨架和图表可视化；Python 才用于严肃回测、组合资金管理、订单簿、手续费滑点、walk-forward 和样本外测试。漂亮 Pine 收益不能作为实盘依据。

风控安全结论

Risk Kernel 必须是确定性规则引擎。LLM 只能输出 proposal，不能输出 command；所有交易动作必须经过 schema 校验、权限校验、风控重算和审计。

build spec

产品目标

在 QuantDinger 框架内新增 H5 AI Trading Command Center，使用户可以完成：标的选择、研究任务、H5 策略评估、场景推演、风控审核、执行授权、交易复盘。

非目标

MVP 不承诺预测价格，不承诺稳定收益，不默认真钱自动交易，不把任一指标当成唯一买卖依据，不做绕过风控的快捷下单。

成功指标

指标目标衡量方式原因
风控覆盖率100% 执行动作必须有 RiskDecision审计日志防止策略直接绕到交易 API。
拒绝可解释率95%+ 拒绝/降级能说明原因RiskEvent 字段完整度让“不交易”成为可复盘结果。
研究可追溯率每个信号绑定 ResearchBriefSignal 关联检查避免无来源、无证据的 AI 口胡。
回测到实盘一致性同一 StrategySpec 驱动 Pine/Python/Live参数版本比对减少回测一套、实盘一套。
最大亏损控制单笔、日亏损、连续亏损均可配置Paper trading 验证赚钱不知道多少，亏损必须先知道。

核心公式

单笔最大亏损 = abs(entry - stop) * qty * contract_value + fee + slippage_buffer。

最终仓位取最小值：风险预算、杠杆限制、流动性限制、仓位上限、相关性上限、交易所最小/最大下单规则。

两套资管模板

Account State Template：账户级状态机，控制 normal、conservative、reduce_only、frozen。

Strategy Budget Template：策略级预算，控制单元升级、利润锁定、阶段降级、试错次数。

H5 StrategySpec 最小字段

字段组字段用途验收标准

产品反模式：这些做法禁止进入 MVP

LLM 直接下单

Agent 输出只能是 Decision Packet，不能直接生成交易命令。交易命令必须经过 deterministic Risk Kernel。

回测即实盘

任何漂亮回测都只能证明规则值得继续测。没有样本外、paper、shadow 和执行日志，不允许开启真钱 API。

指标神化

Keltner、Wyckoff、VSA、均线、2B 都只是证据对象。单个指标不得成为自动下单理由。

权限过大

Research Agent 默认 read-only；Trading Token 默认 paper-only；Live 权限必须按账户、策略、标的、额度、过期时间限制。

一坨策略

信号、风控、资金管理、执行、复盘必须分层。否则亏损后无法知道是策略错、仓位错还是执行错。

忽略不下单

等待、拒绝、降级、冻结都必须是一等结果，且要进入日志和复盘。会不做才是不败的开始。
