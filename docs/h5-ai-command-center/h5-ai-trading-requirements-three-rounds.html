H5 AI Trading Command Center 三轮需求打磨

目标：把 research、技术判断、量化交易、通知、自我交易、风控资管、安全、自我成长升级成 10 分交易飞控需求。

看八大能力 看开发路径

结论：这套系统能做，但 10 分版本必须做成“交易飞控系统”，不是“自由自嗨交易机器人”。

八大能力可以形成闭环：Research 负责信息处理，技术判断负责市场结构和工程可执行性，量化交易负责规则化验证，实时通知负责触达与审批，自我交易负责受控执行，风控资管负责最大亏损边界，安全保障负责权限与密钥，自我成长负责复盘和策略晋级。核心原则是：AI 可以越来越会判断，但不能越来越自由地下真钱单；系统越聪明，风控和审计越要硬。

最重要的需求定义：系统不仅要告诉你“做什么”，还要高质量地告诉你“为什么不做”。不交易、等价格走到预案点、认输退出，都是一等公民能力。
Product ShapeFlight Control交易飞控，不是交易机器人。

0. 10 分价值需求标准

所有模块都要服务真实交易质量，而不是服务功能清单。

10/10 requirement

第一价值：少犯错

系统必须能识别并阻止冲动交易、过度交易、重仓、信号过期、连续亏损后继续交易。

第二价值：控亏损

每个 order intent 必须先算 max_loss，并关联账户状态、策略预算、日损和连续亏损降级。

第三价值：会等待

Scenario Planner 必须把“不做、等、降级、冻结”作为一等 action，而不是只生成买卖点。

第四价值：可复盘

Decision Ledger 必须记录每次信号、拒绝、等待、止损、错过机会和用户反馈。

第五价值：会进化

Growth Curator 只能生成候选版本，必须经过 backtest、paper、shadow 和人工批准后晋级。

第六价值：私有优势

H5 Excel、你的交易哲学、多 agent research 和真实复盘数据要沉淀成别人难复制的情境库。

10 分验收指标：Bad Trade Avoided、Max Loss Known、Risk Rejection Quality、Scenario Prepared、Review-to-Improvement Conversion。后续 PRD v0.3 必须围绕这些指标写。

1. 三轮需求打磨

把愿景逐轮压成边界、模块和验收标准。

Three rounds
Round 1能力定义

先定义“做到”是什么意思。Research 不是聊天总结，而是带来源、时间戳、反方意见、置信度和行动影响的 evidence packet；自我交易不是放任自动下单，而是在前端授权、风控通过、状态机允许后生成或执行订单意图；自我成长不是自动改生产策略，而是复盘、归因、生成候选改进并走影子验证。

Round 2系统落地

把能力落成 8 个子系统：Source Hub、Research Desk、H5 Technical Engine、Strategy Lab、Event & Notification Bus、Execution Desk、Risk & Treasury Kernel、Security & Growth Loop。每个子系统有输入、输出、权限、失败模式和审计记录。

Round 3验收开发

把需求变成可开发路径：P0 只做最能证明 10 分价值的窄闭环：research packet、H5 评分、场景推演、Risk Kernel、通知、paper、Decision Ledger、Weekly Review；P1 做 Pine/Python 回测一致性、shadow、半自动挂单草稿；P2 才做小额白名单 live；P3 才谈多市场自动交易。

三轮打磨后的产品判断：第一版不是追求功能全，而是追求纪律强。一个能每天帮你少犯错、少乱做、少重仓、少追涨杀跌的系统，比一个会生成很多信号的系统更有价值。10 分版本必须先证明“少做坏交易”，再证明“多抓好交易”。

2. 八大能力需求定义

每个能力都用“输入、处理、输出、验收、边界”定义。

Capability spec
Research信息处理与证据包
做到的定义

系统能围绕标的/主题自动收集行情、新闻、宏观、链上、公告、社媒和历史交易结果，产出带来源、时间戳、矛盾点和行动影响的 research packet。

技术路径

Source Hub + 多 agent：Source Collector、Macro/News、Market Microstructure、Bull/Bear Debate、Risk Analyst、Editor。输出只进 Decision Packet，不直接生成订单。

验收标准

每份报告至少包含 3 类来源、明确 stale warning、反方观点、证据强弱评级、对 H5 场景 A/B/C/D 的影响。

边界

无来源不下结论；过期来源降权；社媒情绪只能作为辅助证据，不能替代价格和风险。

技术判断市场结构与工程可执行性
做到的定义

系统能用 H5 框架判断市场所处阶段、中轴级别、波动状态、Keltner/ATR 距离、均线成本、2B/假突破、量价分歧和盈亏比。

技术路径

H5 Technical Engine 把 Excel 规则字段化为 StrategySpec；中轴随品种波动和交易时长选择；日内优先 5m/15m，波动极端时自动提示降级或缩仓。

验收标准

任何信号卡必须显示：当前结构、触发条件、失效条件、最多亏多少、目标空间、是否值得等待。

边界

Keltner、Wyckoff、MA、VSA 都是证据层，不是宗教；评分达标也只能进入风控，不等于可下单。

量化交易规则化、回测、纸面、影子
做到的定义

系统能把 H5 策略方案转成可版本化的 StrategySpec，并导出 Pine 快速回测、Python 严肃回测、paper order、shadow signal。

技术路径

Strategy Registry + Backtest Lab + Paper Simulator。所有策略保存代码 hash、参数快照、数据范围、手续费、滑点和样本外表现。

验收标准

策略升级必须同时具备：Pine 规则可跑、Python 结果一致、paper 至少 2-4 周、最大回撤和风控拒绝记录可查。

边界

禁止只看收益率升级；禁止暴力调参后直接实盘；禁止把历史拟合当成未来优势。

实时通知事件触达与审批
做到的定义

系统能对 research 完成、信号触发、风险拒绝、挂单待批、订单成交、止损、异常、日损接近阈值等事件实时通知。

技术路径

Event Bus + Notification Router，支持 Telegram、Slack、Email、Webhook，后续可接 WeChat/Push。消息带事件等级、过期时间、审批按钮或回链。

验收标准

P0 通知延迟小于 5 秒；重复事件自动合并；高风险事件必须多通道；每条通知可回溯到 decision/order/risk id。

边界

通知不是执行；TradingView webhook 只能作为外部触发源，进入系统后必须重新检查价格、时间戳、风控和持仓状态。

自我交易受控自主执行
做到的定义

系统能在不同模式下完成从信号到订单意图再到执行的流程：SIGNAL_ONLY、PAPER、SEMI_AUTO、AUTO_API。每一级都有权限、额度和状态机。

技术路径

Execution Desk 只接受 Risk Kernel 批准后的 order intent；使用 idempotency key、client order id、订单状态同步、撤单和异常恢复。

验收标准

SEMI_AUTO 必须前端确认；AUTO_API 只允许白名单策略、白名单标的、小额额度、预设止损、数据新鲜、kill switch 正常。

边界

LLM 永远不能直接持有交易 API key，不能自行放大仓位，不能自行改变 stop loss，不能绕过人工授权升级模式。

风控资管最大亏损与资金状态机
做到的定义

系统能在每个交易前回答：最多亏多少、今日还能亏多少、连续亏损是否触发降级、账户状态是否允许交易、策略预算是否还有试错次数。

技术路径

Risk & Treasury Kernel：账户级状态机 + 策略级预算模板 + ATR 仓位 + 相关性/流动性/杠杆限制 + 日损和连续亏损降级。

验收标准

所有 order intent 都有 max_loss、risk_pct、reward_r、daily_loss_remaining、position_after_order、risk_decision。

边界

系统可以不知道本单赚多少，但必须知道最多亏多少。收益目标可以推演，亏损边界必须计算。

安全保障权限、密钥、提示注入防御
做到的定义

系统能确保 agent、用户、策略、交易所 key、执行 adapter 各有权限边界；任何外部内容不能越权触发交易或泄露密钥。

技术路径

RBAC + scoped API keys + secret vault/.env + sandboxed tools + prompt injection filter + signed action + audit log + read/write connector separation。

验收标准

无密钥进入 prompt；所有 live action 需要 operator/session/strategy/risk/action hash；安全扫描覆盖 SSRF、prompt injection、excessive agency、API abuse。

边界

Research agent 只能读；Execution agent 只能执行已批准订单；Risk agent 只能否决或降级，不能创建方向信号。

自我成长升级复盘、记忆、候选晋级
做到的定义

系统能把每次 research、信号、拒绝、成交、止损、错过机会和用户反馈沉淀为记忆，并周期性生成改进候选。

技术路径

Decision Ledger + Reflection Worker + Skill/Strategy Curator + Evaluation Harness。学习结果进入候选版本，经过 backtest、paper、shadow 和人工批准再晋级。

验收标准

每周生成复盘报告：哪些信号有效、哪些被风控救了、哪些错过但不该追、哪些策略需要降级、哪些参数值得候选测试。

边界

自我成长不能自动改 live 策略；它只能提出版本候选和理由，不能把“我感觉变强了”当成生产部署凭证。

3. 推荐系统架构

用 QuantDinger 的产品骨架，换成 H5 的决策核心和更硬的风控权限。

Architecture
01Source Hub

行情、K线、盘口、新闻、链上、公告、TradingView webhook、用户笔记。

02Research Desk

多 agent 生成 evidence packet、反方观点和行动影响。

03H5 Engine

中轴、Keltner/ATR、MA 成本、2B、VSA、场景 A/B/C/D。

04Strategy Lab

StrategySpec、Pine、Python backtest、paper、shadow。

05Risk Kernel

账户状态、策略预算、仓位、日损、连续亏损、Kill Switch。

06Execution Desk

Signal、Paper、Semi-auto、Auto API；订单意图和状态同步。

07Notification Bus

Telegram、Slack、Email、Webhook；审批、异常和复盘提醒。

08Growth Loop

Decision Ledger、Reflection、候选策略、评估和晋级。

架构核心：LLM 在 Research、解释、复盘和候选升级里发挥能力；交易执行由状态机、风控和适配器完成。AI 的聪明用来减少人性错误，不用来绕过纪律。

5. 状态机和权限

没有状态机，就没有真正的自我交易和自我成长。

State machine

策略状态

  • draft：只允许研究和编辑。
  • backtested：允许导出报告，不允许下单。
  • paper：允许模拟订单。
  • shadow：真实行情影子跟踪。
  • semi_auto：可生成挂单草稿，需人工确认。
  • live_locked：小额白名单自动执行。

账户状态

  • normal：按常规风险执行。
  • conservative：缩仓、提高门槛。
  • reduce_only：只减仓，不开新仓。
  • frozen：停止交易，只允许复盘。
  • manual_override：人工接管，但审计继续。

订单状态

  • proposed：策略提出。
  • risk_checked：风控完成。
  • awaiting_approval：等待前端确认。
  • submitted：已提交交易所。
  • acked / partial / filled。
  • canceled / rejected / stale。

权限矩阵

主体可读可写禁止
Research Agent公开数据、研究库、历史决策research packet、证据标签订单、密钥、风控参数
H5 Technical AgentK线、指标、StrategySpec评分、场景、技术解释绕过评分门槛、直接下单
Risk Kernel账户、持仓、策略预算、订单意图批准、拒绝、降级、冻结生成方向观点、提高风险预算
Execution Adapter已批准 order intent订单提交、撤单、状态同步修改数量、止损、方向
Growth Curatorledger、结果、复盘、用户反馈候选版本、降级建议直接修改 live 策略
Operator全局仪表盘、审计、通知模式切换、审批、Kill Switch关闭审计、绕过 P0 风控

8. 安全与失败模式

交易系统最大的安全问题不是黑客，而是系统在错误时还很自信。

Safety
风险典型场景必须防线
Prompt Injection新闻网页、社媒内容、公告里诱导 agent 泄密或下单外部内容隔离为 evidence；agent 无交易密钥；工具 scope 白名单。
Excessive AgencyAI 把研究结论直接升级成交易执行Decision Packet 与 Order Intent 分离；Risk Kernel 和前端审批硬门。
数据延迟TradingView webhook 到达时价格已过期重新拉取当前价格、盘口、时间戳；过期事件标记 stale。
部分成交订单只成交一部分，止损/止盈未同步user data stream 同步；position reconciler；异常冻结。
连续亏损策略短期失效但仍持续交易连续亏损降级、日损冻结、策略预算耗尽后只复盘。
过拟合升级参数只在历史数据漂亮walk-forward、样本外、paper/shadow、候选版本审批。
密钥滥用API key 被日志、prompt 或前端泄露secret vault/.env、最小权限 key、IP 白名单、日志脱敏。
